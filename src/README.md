# Developer notes (GP6P01)

Setup, building and playing are covered in the [top-level README](../README.md). This file
covers the decomp project itself and gives notes on each patch.

## Layout

- `orig/GP6P01/`: your Dolphin extract of the PAL disc. It must contain `sys/main.dol` and
  `files/`, including the RELs. Not tracked.
- `config/GP6P01/`: Europe input hashes (`build.sha1`) and the DOL and REL symbols and splits
  generated by decomp-toolkit. `config/GP6E01/` is the upstream US config, kept for
  reference only.
- `src/`, `include/`: C source and headers carried over from the US decompilation, plus the
  new Close Call minigame (`src/REL/closecallDll/`). The carried-over US source has not been
  verified as matching the European binaries.
- `tools/`: the patch scripts. See [tools/README.md](tools/README.md).
- `docs/patching-guide.md`: **read this before adding or changing a patch.** It covers the
  code space map, shared helpers, REL hooks, message banks and known hazards.

For the `config/` file formats (`symbols.txt`, `splits.txt`) and decomp-toolkit itself, see the
upstream [dtk-template docs](https://github.com/encounter/dtk-template/tree/main/docs).
- `tools/bin/`: put decomp-toolkit v1.8.4 (`dtk-windows-x86_64.exe`) and Ninja 1.13.2
  (`ninja.exe`) here. Several scripts call them by these paths.
- `build/GP6P01/`: generated by `configure.py` and ninja. The patch scripts edit it in place.
  Not tracked.

Design notes are in [../plans](../plans) (bonus stars, orbs, minigame pools, Faire Square)
and [../boards](../boards) (board layouts and space edits). Paths like `plans/orbs/star-trap.md`
below are relative to the repository root.

The project targets `GP6P01`. Its DOL SHA-1 is
`a13734d31e305e8d18e8f6f2c94082b894218042`. The 131 extracted RELs were
checked into the Europe config by their own SHA-1 hashes. The current config
does not use a matching map file.

## Reconfigure

Run commands from this directory:

```powershell
python .\configure.py --version GP6P01 --dtk .\tools\bin\dtk-windows-x86_64.exe
.\tools\bin\ninja.exe
```

The initial unmodified Ninja build completed compilation and linking. All 131
rebuilt RELs match the European originals exactly. The rebuilt DOL is 32 bytes
smaller and has a different SHA-1 from the original; `dtk dol diff` reported no
symbol differences. The DOL baseline therefore was not an exact whole-game
match.

The DOL mismatch should be investigated before treating this as a fully
matching build.

Do not substitute `GP6E01` binaries, and do not treat its symbols, splits or
source matches as verified for Europe.

## Bowser Bonus patch

The Bowser Bonus patch gives four equally likely results: all of the current
player's coins, two Stars, 30 coins, or one Star. The existing 30% chance of
Bowser Bonus versus 70% chance of a Bowser Mini-Game is unchanged. The all-coins
result is capped at the player's current coin balance, and the two-Star result
cannot remove more Stars than the player has.

After building the DOL, apply the Bowser Bonus patch:

```powershell
.\tools\bin\ninja.exe build\GP6P01\main.dol
python -m tools.patches.apply_bowser_bonus_patch
```

Replace the extracted `&&systemdata\Start.dol` with
`build\GP6P01\main.dol`. For the generic two-Star message, also replace the
extracted English `mess\messdata_eng.bin` with
`build\GP6P01\files\mess\messdata_eng.bin`; use the game's English language
setting. The all-coins outcome uses the existing Bowser all-coins message.

The selector uses the existing visual faces, so its 10-coin face is still used
for the two-Star result; the outcome dialogue identifies the actual reward.

## Bowser Mini-Game patch

Run after the Bowser Bonus patch. It changes the Bowser space to 50% Bowser
Bonus / 50% Bowser Mini-Game, and the Mini-Game penalty is an even three-way
split between "hand over all their coins", "hand over all their Orbs" and
"hand over a Star" (the vanilla game randomly picks half coins, all coins or all
Orbs). Only the losers pay. If the roll picks the Star penalty but no player has
a Star, Bowser says "Nobody has a Star? Hah, then I guess I'll take your coins
instead" right after the roll, before the Mini-Game, and the penalty becomes all
coins. Otherwise a loser with no Star loses nothing, and if no loser has one
Bowser says so. The Star penalty reuses the Orb-removal path (code cave
at `0x80004918`).

```powershell
python -m tools.patches.apply_bowser_minigame_patch
```

Replace `&&systemdata\Start.dol` with `build\GP6P01\main.dol`, and
`mess\messdata_eng.bin` with `build\GP6P01\files\mess\messdata_eng.bin` (two new
English Bowser messages; other languages are not updated). The English file is
chained: run this after the Bowser Bonus / Bonus fix patches (re-running those resets the Bowser bank, so re-run this one afterwards).

## Applying all patches (quick reference)

Run from the repo root, in this order (each script is safe to re-run):

```powershell
python -m tools.patches.apply_bowser_bonus_patch
python -m tools.patches.apply_bowser_minigame_patch
```

Outputs, to copy into the extracted game before rebuilding the image with GCR:

- **Required:** `build\GP6P01\main.dol` replaces `&&systemdata\Start.dol`. It contains every gameplay change.
- **Optional:** `build\GP6P01\files\mess\messdata_eng.bin` replaces `files\mess\messdata_eng.bin`. It only rewords the English Bowser Bonus Star message; play in English to see it.

Status: applied and built; not yet tested in Dolphin.


## Bowser Bonus fix patch

Run after the Bowser Bonus patch (and before or after the Mini-Game patch). It keeps the vanilla five wheel faces and remaps the outcomes to:

- **5 coins:** take all coins. Bowser says "Gimme ALL your coins!".
- **10 coins:** Bowser says "Wow pal, my scratcher paid off... I feel generous!" and gives the player 100 coins.
- **20 coins:** take 1 Star ("juicy prize" message; "You don't have a Star" if the player has none).
- **30 coins:** take 30 coins. The message always says 30; if the player has fewer, only what they have is taken.
- **Star:** take 2 Stars, or 1 Star if the player only has one.

The 20-coin and Star faces share the "Hand over a Star or two" message.

The English message file must be replaced too: the patch adds a new Bowser message and shortens the last page of the "no coins" message to make room. The file size is unchanged.

```powershell
python -m tools.patches.apply_bowser_bonus_patch
python -m tools.patches.apply_bowser_bonus_fix_patch
python -m tools.patches.apply_bowser_minigame_patch
```

Copy `build\GP6P01\main.dol` over the extracted `&&systemdata\Start.dol`.
Also copy `build\GP6P01\files\mess\messdata_eng.bin` over `files\mess\messdata_eng.bin` (required for the new messages; play in English).

## DK Bonus outcomes patch

Run after the DK split patch. It changes the DK Bonus faces to:

- **5:** the vanilla Star cutscene (1 Star).
- **10:** the vanilla Star cutscene plus one extra Star (2 Stars total).
- **20:** lose up to 30 coins, taking all coins if the player has fewer than 30.
- **30:** award 50 coins (vanilla coin path).
- **Star:** no effect; DK says "Sorry, not this time, pal!"

The 5- and 10-faces run the unmodified vanilla Star branch; the 10-face adds
one Star just before it. The 20- and Star faces go through the vanilla coin
branch so the dice barrel is dismissed normally: the 20-face writes
`-min(30, coins)` into its result-table slot at runtime and shows "DK takes N
coin!", and the Star face runs it with zero coins and skips the coin effects.

The English message file is rebuilt with two new DK messages. Replace it too
and use the English language setting.

```powershell
python -m tools.patches.apply_dk_split_patch
python -m tools.patches.apply_dk_bonus_patch
```

Copy `build\GP6P01\main.dol` over the extracted `&&systemdata\Start.dol`.
Also copy `build\GP6P01\files\mess\messdata_eng.bin` over
`files\mess\messdata_eng.bin`.
The English message file grows by 68 bytes to add the new DK message records.
Status: applied and built; needs in-game retesting in Dolphin.

## Dunk Bros 2v2 patch

Independent of the other patches (it only edits the m699 entry in the minigame table in the DOL). Dunk Bros (`m699`, "BASKET") is a 2v2 game but was typed as a "Last"/rare game, so the board 2v2 pool (which selects by type) never picked it. The patch changes its type to 2v2, replaces `MG_FLAG_RARE` with `MG_FLAG_4P`, and allows it to appear in the normal 2v2 Minigame Mode category and use the normal 2v2 ranking screen instead of the Rare-game result path. The current patch does not yet restore the 10-coin winner reward; Dunk Bros. still needs a result-reporting fix.

```powershell
python -m tools.patches.apply_dunk_bros_patch
```

Copy `build\GP6P01\main.dol` over `&&systemdata\Start.dol`. Status: applied and tested in Dolphin; the normal result screen appears, but no coins are awarded yet.

### Dunk Bros result investigation

The missing payout is not caused by the minigame table type or flags. The normal post-minigame flow consumes the shared per-player result table at `lbl_80282E48`; its result values are read by `fn_801F5854` and then converted into the ranking/reward data. Normal minigame RELs write those values before returning to the main DOL.

Dunk Bros does not write any result values to `lbl_80282E48`. Its REL instead tracks the outcome in its private `lbl_1_bss_15C` array: `fn_1_1244(player)` marks a winning player with `1`, and `fn_1_1264()` waits until all four players have been marked. Because that private result is never transferred to the shared table, the ranking screen can still be displayed after the metadata patch, but the reward code sees no valid winners and awards `+0` coins.

The result handoff has now been added to `m699Dll`'s `fn_1_1264()` completion path. Once all four private winner flags are set, it copies each player's result into `lbl_80282E48 + 0x06`: winners are written as rank `0` and losers as rank `1`. The write is idempotent because the completion check is polled. The REL still needs to be rebuilt and tested in Dolphin; the checked-in generated object is not automatically rebuilt by the current Ninja graph.

## Random Bonus Star patch (Trap Merchant count)

`tools\patches\apply_random_bonus_patch.py` also builds and deploys the DOL, REL and English messages itself (it copies into `root`). The Trap Merchant Star counts orbs landed on (`GwPlayer+0x16`) plus trap orbs passed over. Pass-over orbs (type 2: ids 20-25) never reach the vanilla landing counter, so a hook at `0x801D4668` (cave `0x80004018`) increments the same counter on the pass-over path, capped at 99. The landing counter at `0x801D4764` is left vanilla. Details in `plans/bonus-stars/README.md`.

```powershell
python -m tools.patches.apply_random_bonus_patch
```

Status: applied, built and deployed; pass-over counting not yet tested in Dolphin.

## Mini-game Star counts wins

The Mini-game Star goes to whoever **won the most minigames**, not whoever earned the most minigame coins. The ceremony shows the count ("Total Mini-game wins: N").

- `tools\patches\apply_minigame_wins_patch.py` rebuilds `resultDll` from asm. A call at the start of `fn_1_37D8` counts wins into `GwPlayer+0x2A` (padding), capped at 99. Who counts as a winner:
  - Battle: 1st place (`+0x28 == 0`; nobody if all four tie).
  - m642: coins picked up (`+0x26 > 0`), because it never writes `+0x28`.
  - Otherwise: got the winner's 10-coin bonus (`+0x28 > 0`).
- Only end-of-turn minigames count (4P, 1v3, 2v2, Battle). Duel, Bowser and DK minigames skip resultDll, so they don't count.
- `apply_random_bonus_patch.py` reads `+0x2A` into the Mini-game Star stat (tag mode: the higher of the two teammates). It resets the counter at board start by widening `sth r5,0x28(r3)` at `0x8014C00C` to `stw`. It also adds the "wins" winner pages and rewords the tag intro.
- Order: run it after random_bonus and before mgtable_move (`apply_all.py` does this). It writes `build\GP6P01\files\dll
esultDll.rel`. If mgtable_move is already applied, it retargets the minigame-table relocations itself.

```powershell
python -m tools.patches.apply_minigame_wins_patch
```

Status: applied, built and deployed; not yet tested in Dolphin.

## Unlucky Star

A new bonus award, the **Unlucky Star**, goes to whoever lost the most to bad luck. The score is coins lost plus 30 coins for every Star lost. It joins the random bonus pool as award 7, so the ceremony draws 3 of 7. The ceremony shows the score ("That's N coins' worth of losses!").

What counts as bad luck:

- Red spaces.
- Hit and trap orbs (orbs 10-25, including the Star Trap orb and Thwomp's toll).
- Round of Miracles (the Miracle space).
- Bowser spaces: the Bowser Bonus and the Bowser Mini-Game penalty.
- DK spaces.
- Boo stealing from you. The player who calls Boo is paying, so their own coins don't count.
- Spending never counts.

`tools\patches\apply_unlucky_patch.py` hooks the two coin/Star setters (`fn_8003CDA8` at `0x8003CE3C`, `fn_8003CF28` at `0x8003CF8C`). Every decrease goes into `GwPlayer+0x104` (`coinGraph[51]`, unused), capped at 9999, but only during one of the events above. How it decides:

- **Red spaces:** a flag is set around the red-space call at `0x80176AC4`.
- **Orbs and special spaces:** the current process, or one of its parents, must be an event process in `lbl_802DC2E0`, and the event id must be 10-25, 42, 43, 44 or 46.

The code is in DOL section 17 (`0x802F9A00`), so it runs last in `apply_all.py`. `apply_random_bonus_patch.py` adds the award and its text, and resets the counter at board start (`stw r5,0x104` in its board-init cave).

```powershell
python -m tools.patches.apply_unlucky_patch
```

Status: applied, built and deployed; not yet tested in Dolphin. Untested assumptions:

- After the Bowser Mini-Game returns, the penalty still runs inside the Bowser event process.
- Coin animations run in the event's own process or one of its children.

## Star Trap Orb patch

Adds a new Piranha-style hit orb (orb ID 14): a player who lands on it loses 1 Star (if they have one) and the orb's owner gains it. It reuses the Piranha Plant handler (`fn_801A3BC8`); five of its coin sites branch on the orb ID. Independent of the other patches, except that it chains the English message file, so run it after the Bowser and DK patches. (The Bowser, DK and Random Bonus patches now write only their own message banks, so the order between them no longer matters for text.)

```powershell
python -m tools.patches.apply_star_trap_orb_patch
```

- Orb data: `capsuleData` row 14 (`0x80266E0C`; Soluna sun icon, price 10, rarity 'D') and event row 14 (`0x80268688`, copy of Piranha's). Name and description go in banks 56 and 55 (records 37 and 59); the event messages go in bank 54 (records 21 and 22).
- Obtainable: a hook at the end of `mbCapListRead` (`0x801C801C`) adds Star Trap to the six main board lists (those with at least 5 orbs; the small special-board lists are left alone). Its weight in each weight group and rank is the rounded average of the non-zero weights already in that list, so it is about as common as a typical orb (roughly 10-17% of a draw), and its price falls back to 10. `STAR_TRAP_ODDS = "boost"` in the script switches to a fixed weight of 100 in every list for testing.
- Code caves: `0x80003830`, `0x80003918`, `0x80003A18`, `0x80003B18` (zero padding in the TRK vector area, like the other patches).
- Copy `build\GP6P01\main.dol` over `&&systemdata\Start.dol`. Copy all six `build\GP6P01\files\mess\messdata*.bin` files over the extracted `files\mess\` copies; the non-English files use the English text.
- Status: applied and built; not yet tested in Dolphin. Computer players look the orb up as Piranha Plant in the AI chance table (hook at `0x801C93A0`, cave at `0x80003890`), so they should now use and place it like a Piranha Plant; untested. Design notes: `plans/orbs/star-trap.md`.
